# Files Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Options switch that moves the whole files panel (tree, editor, page preview) into its own OS window "desk — pliki".

**Architecture:** A second Tauri window `files` loads its own page (`files.html` → `src/files-main.ts`), which builds the existing `Side` in a detached mode. In the main window, `app.ts` talks to a stand-in (`FilesWindowPanel`) with the same methods it uses on `Side`. The stand-in sends commands to the files window as Tauri events and keeps the state the files window reports back. Rust creates, shows and hides the window, guards it with the desk lock, gives it its own capability and remembers its place. The native page preview becomes a child of whichever window asked for it.

**Tech Stack:** Tauri 2 (Rust), vanilla TS + vitest, Vite (multi-page build).

**Spec:** `docs/superpowers/specs/2026-11-19-files-window-design.md` (Polish, binding)

## Global Constraints

- Mode: `layout.filesWindow: boolean` (Rust `files_window`, serde camelCase, default false = the panel at the side, as today).
- Window: label `files`, title "desk — pliki" (en "desk — files"), page `files.html`, normal system frame, background as the main window (`#0b0d10`). It is created on demand, never at start. desk always starts with it closed; only the mode is remembered.
- Its place is saved like the main window's, in `files-window.json` next to `window.json`, and it skips a place on an unplugged monitor.
- Closing the files window hides it (state, unsaved edits and the preview are kept); switching the mode off destroys it.
- Lock: `lock_desk` hides the files window. The command that shows or creates it refuses while locked. Unlock shows it again only if it was visible before the lock.
- Files window capability (`capabilities/files.json`, webviews `["files"]`): only the commands the panel uses. It never includes `pty_write`, `quit_desk`, `save_layout`, `open_session` or `kill_session`. The `preview` webview gets no capability, as today.
- Event protocol (`src/files-link.ts`, shared by both pages):
  - main → files: event `files:do` with payload `FilesCommand`;
  - files → main: event `files:said` with payload `FilesReport`;
  - exact unions in Task 3.
- Shortcuts in the files window:
  - ⌘S saves in the editor (as today);
  - ⌘F shows the tree;
  - ⌘W closes (hides) the window;
  - ⇧⌘F focuses the main window and opens "Szukaj w plikach" there;
  - Esc behaves as in the panel today;
  - other desk shortcuts do nothing there.
- Find in Files popup stays in the main window; a hit opens in the files window.
- Commits in Polish, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Restore `src-tauri/permissions/autogenerated` churn before committing; commit only new `*.toml` files of new commands.
- Commands run from `desk-main` with literal relative paths (no `cd`, no shell variables, no `source`, no env-var prefixes). Node 26, as in `.nvmrc`. Privacy: no server names, key names or home paths in code, commits or docs.

## Review Focus

1. Switching the mode while a file is being edited with unsaved changes: the edits must not be lost silently. Expect the same "save?" path `Side.stopEditing()` uses today before the side panel closes. Task 4 test: `switching to the window asks to save a dirty file first`.
2. A command sent before the files window has finished loading (⌘F right after the switch) must still happen once the window reports `ready`, in order. Task 4 test: `commands wait for ready and replay in order`.
3. Lock while the files window is visible, then unlock: the window must stay hidden during the lock and come back after. The same goes for a `files_window_open` attempted while locked, which is refused. Task 1 tests: `open_is_refused_while_locked` and `unlock_shows_only_what_was_visible`.
4. The preview opened in the side panel, then the mode switched: the old native view must not stay glued over the main window. Task 2 test: `a preview asked from another window is rebuilt there`.
5. The language or theme changed in Options while the files window is open: its labels and colors must follow at once. Task 3 test: `settings command relabels and rethemes`.

- Produces in `src/files-link.ts`:

```ts
export interface FilesSettings { browser: string; linkClick: string; fileEditor: string; language: string; theme: string; uiScale: number; keys: Record<string, string> }
export type FilesCommand =
  | { op: "showFiles" } | { op: "toggle" } | { op: "browse" }
  | { op: "open"; link: string; project?: string }
  | { op: "openAt"; file: string; line: number; project: string }
  | { op: "project"; project: string | null }
  | { op: "settings"; settings: FilesSettings };
export type FilesReport =
  | { op: "ready" }
  | { op: "state"; open: boolean; filesShown: boolean; shown: string | null }
  | { op: "insert"; text: string } | { op: "terminal"; path: string } | { op: "find" };
export const TO_FILES = "files:do";
export const TO_MAIN = "files:said";
/** The files window's key: what desk shortcuts do there (null: nothing). */
export function filesWindowKey(action: Action | null): "showFiles" | "hide" | "find" | null;
```

- `Side` gets a constructor option `{ detached?: boolean }`:
  - detached means no splitter, it fills its parent, and × hides the window (`api.filesWindowHide()`);
  - `Side.shown(): string | null` gives the file being edited, else the address shown, else null.
- `files-main.ts`:
  - calls `bootstrap` to fill a local `FilesSettings` and `project` copy;
  - applies the theme, `uiScale`, language and custom keys;
  - builds `new Side(onLayout, ctx, { detached: true })` into `#app`;
  - listens to `TO_FILES`;
  - reports `state` to main after every open, close or show change;
  - sends `ready` once.

**Interfaces:**
- Consumes: Tasks 1–3 (`files-link.ts` types, commands).
- Produces:
  - `interface Panel { readonly el: HTMLElement; readonly isOpen: boolean; readonly filesShown: boolean; browse(): void; toggle(): void; toggleFiles(): void; showFiles(): void; showFind(seed?: string): void; projectChanged(): void; relabel(): void; browserChanged(): Promise<void>; open(link: string, project?: string): Promise<void>; close(): void }`. `Side` implements it.
  - `class FilesWindowPanel implements Panel`, with:
    - `el`: a hidden empty element;
    - every method sends a `FilesCommand` (opening the window first with `api.filesWindowOpen()`);
    - the commands queue until `ready` arrives;
    - `isOpen`, `filesShown` and `shown` come from the last `state` report;
    - it owns its own `FindPanel`, whose `open` sends `openAt`;
    - `insert` and `terminal` reports call the main ctx;
    - a `find` report runs `showFind()`.
  - `SettingsContext.setFilesWindow(on: boolean)`.
